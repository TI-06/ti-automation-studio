# 公開ツール4本 共通設計

## 1. 目的

TI AUTOMATION STUDIO の「公開ツール」を、単なるデモ置き場ではなく、検索流入・実用性・技術力の証明を兼ねる主要コンテンツへ作り直す。

公開する4本は以下。

1. Excel差分比較・変更箇所チェッカー
2. CSV・Excel データ整理・クレンジングツール
3. Excel・CSV ダッシュボード自動作成
4. 業務自動化診断・工数削減シミュレーター

すべて完全無料・ログイン不要とし、利用開始前のメール登録や会員登録を要求しない。

## 2. 対象ユーザー

主対象はエンジニアではなく、会社員・中小企業・個人事業主などの業務ユーザー。

- ExcelやCSVを日常業務で使う
- システム用語には詳しくない
- 「いま困っている仕事をすぐ片付けたい」という検索意図を持つ
- SaaS導入ではなく、必要な時だけ使える無料ツールも求めている

技術用語を知っている前提のUIにしない。

## 3. 役割分担

### 検索流入を狙うツール

- Excel差分比較・変更箇所チェッカー
- CSV・Excel データ整理・クレンジングツール

### 技術力・業務設計力を見せるツール

- Excel・CSV ダッシュボード自動作成
- 業務自動化診断・工数削減シミュレーター

4本とも実務で使えることを優先し、「問い合わせのためだけの疑似診断」「結果を見るために個人情報が必要」といった構成にはしない。

## 4. 共通UX

全ツールの基本操作を以下に統一する。

**入力 → 解析 → 確認 → 保存**

画面上では可能な限り日本語を使う。

- Upload → 「ファイルを選択」
- Analyze → 「解析する」
- Processing → 「処理しています」
- Preview → 「変更内容を確認」
- Export → 「結果を保存」
- Filter → 「絞り込み」
- Reset → 「最初からやり直す」
- Primary Key → 「行を特定する列」

CSV、Excel、PDF、XLSX、APIなど、日本語化すると逆に分かりにくい一般的な用語は英字表記を許可する。

## 5. 処理中表示

ローディングスピナーだけで待たせない。

必ず現在の処理内容を表示する。

例:

- 1 / 4 ファイルを読み込んでいます
- 2 / 4 シート構成を確認しています
- 3 / 4 8,421行を照合しています
- 4 / 4 結果をまとめています

長時間処理では、可能な範囲で処理件数も表示する。

例:

`5,240 / 18,420行を比較中`

UIスレッドを長時間占有する処理は Web Worker へ分離し、画面が固まったように見える状態を避ける。

## 6. エラー表示

エラーコードや英語例外をそのまま表示しない。

悪い例:

`Invalid file`

良い例:

**このファイルを読み込めませんでした**

Excelファイルが破損しているか、対応していない形式の可能性があります。.xlsx または .xls ファイルを確認してください。

エラー文には可能な限り「何が起きたか」「どうすれば直せるか」を含める。

## 7. デザインシステム

TI AUTOMATION STUDIO 本体のブランドを維持しながら、ツール部分は一段プロダクト寄りにする。

### 基本色

- 背景: `#0B0C0E`
- サーフェス: `#111317`
- アイボリー: `#F2F0EA`
- 補助文字: `#A8A8A2`
- シャンパンゴールド: `#C8A96B`

差分・状態表示のために補助色を使うが、原色を多用しない。

### 見た目

- 大きな角丸カードを大量に並べる「AI SaaSテンプレート風」は避ける
- 細い罫線、余白、情報密度、タイポグラフィで業務アプリらしく整理する
- 不要なグラデーション・ネオン・発光表現を避ける
- ツールごとの画面密度は高くても、優先順位を明確にする
- アニメーションは状態変化の理解に役立つものだけ使う

### PC

業務利用を優先し、ツールごとに必要なら左設定パネル・中央作業領域・右詳細パネルを持つ。

### スマホ

PCの3ペインをそのまま縮小しない。

- 一覧・診断・簡易確認はスマホ対応
- 大規模なExcel比較やダッシュボード編集ではPC推奨表示を出してよい
- 重要操作は縦1列へ再配置

## 8. 共通コンポーネント

4本で可能な限り共通化する。

- ツール上部バー
- ファイル選択 / ドラッグ&ドロップ
- ファイル情報表示
- 処理進捗
- エラー通知
- 完了通知
- サマリー数値
- 絞り込みUI
- 結果保存UI
- 「最初からやり直す」
- プライバシー表示
- PC推奨表示

共通部品の見た目・文言・操作感を揃え、4本を別サイトの寄せ集めに見せない。

## 9. プライバシーと処理方式

ツールごとに最適な方式を選ぶが、サーバー送信が不要な処理はブラウザ内で完結させる。

初期4本は、原則として以下を採用する。

- Excel差分比較: ブラウザ内処理
- データ整理: ブラウザ内処理
- ダッシュボード作成: ブラウザ内処理
- 業務自動化診断: ブラウザ内処理

この方式で成立する限り、ユーザーファイルをCloudflare Worker等へ送信しない。

ファイルをブラウザ内だけで処理するツールでは、ファイル選択付近に以下の趣旨を明記する。

> ファイルは外部サーバーへ送信されません。このブラウザ内で処理します。

将来サーバー処理を追加する機能がある場合は、その機能だけ明示し、ブラウザ処理と混同させない。

## 10. 対応規模

ブラウザの安定性を優先する。

初期目安:

- 1ファイル最大20MB
- 1シート最大100,000行を上限
- 50,000行超では処理時間が長くなる可能性を事前表示

上限値は実装時の性能試験で調整可能だが、UIには必ず実際の制限を表示する。

上限超過時にブラウザを固めるのではなく、処理開始前に停止して日本語で理由を示す。

## 11. 公開ツール一覧 `/tools`

現在のカード一覧を、公開プロダクトの入口として再設計する。

### ヒーロー

**仕事で使える、無料の業務ツール。**

補足:

- 登録不要
- そのまま利用可能
- ブラウザ処理のツールではファイルを外部へ送らない

### ツールカード

4本それぞれに実画面を模した高品質なUIビジュアルを持たせる。

アイコン1個だけではなく、「何ができるか」が画像だけでも伝わる構成にする。

カードに表示する情報:

- ツール名
- 一文の用途説明
- 無料
- 登録不要
- 対応形式
- ブラウザ処理かどうか
- 代表機能3点程度
- 「このツールを使う」導線

## 12. ツール詳細URL

ツール説明ページから外部デモへ飛ばす方式をやめ、原則としてURLを開いたページ上ですぐ使える構成にする。

予定URL:

- `/tools/excel-diff`
- `/tools/data-cleaner`
- `/tools/dashboard-builder`
- `/tools/automation-diagnosis`

SEO説明、使い方、FAQなどは同じURL内のツール本体の下部へ置く。

## 13. SEO

各ツールページは検索ランディングページとして成立させる。

共通要件:

- 固有 title
- 固有 meta description
- canonical
- OGP / Twitter画像
- BreadcrumbList
- SoftwareApplication または WebApplication の内容に合う構造化データ
- FAQは実際にページへ表示する内容と一致させる
- ツール本体がJavaScriptで動いても、説明部分・見出し・FAQはクロール可能なHTMLとして出力する

キーワードの不自然な詰め込みは行わない。

## 14. 受注導線

無料ツールの利用を問い合わせで妨げない。

結果画面またはページ末尾に控えめな導線を設ける。

例:

> 毎回この処理を行っている場合は、業務そのものを自動化できることがあります。

導線候補:

- 関連サービス
- 関連開発実績
- 問い合わせ

ツール利用開始前に問い合わせを強制しない。

## 15. アクセシビリティ

- 色だけで変更種別を表現しない
- キーボード操作可能なUIを優先
- focus-visible を維持
- ボタン・入力項目に日本語ラベル
- グラフには数値テーブルまたは説明を用意
- 処理状態は視覚表現だけでなくテキストでも表示

## 16. 技術構成

既存の Astro + TypeScript + Cloudflare Workers 構成を維持する。

ツールUIは必要なページだけクライアントJavaScriptを読み込む。

想定責務:

- Astro: ページ骨格、SEO、説明コンテンツ、共通レイアウト
- TypeScript: ファイル処理、比較、診断、状態管理
- Web Worker: 重いExcel/CSV解析、比較、集計
- ブラウザAPI: ファイル読込、ダウンロード
- Cloudflare Workers: サイト配信。初期4ツールのユーザーファイル処理には使用しない

ライブラリは実装計画時に固定するが、4ツールで同じExcel/CSVパーサーを再利用する。

## 17. 実装の分割

品質を落とさないため、4本を巨大PRで一度に実装しない。

推奨順序:

1. 共通ツール基盤 + Excel差分比較
2. データ整理・クレンジング
3. ダッシュボード自動作成
4. 業務自動化診断
5. 公開ツール一覧を4本完成版へ最終調整

共通基盤は最初のツール実装時に作り、2本目以降で必要なものだけ拡張する。将来機能を先回りした過剰な抽象化は行わない。

## 18. テスト方針

### ユニットテスト

- ファイル種別判定
- 行照合
- 差分分類
- データ整理ルール
- 集計ロジック
- 診断スコアリング
- 工数計算

### コンテンツ/SEOテスト

- 4URLが存在する
- 固有title/description
- 構造化データ
- 内部リンク
- 日本語主要UI文言

### ビルド

- `npm test`
- `npm run build`

### ブラウザでの実利用確認

CIで可能な範囲に加え、公開前に少なくとも以下のファイルパターンを手動確認する。

- 小規模Excel
- 10,000行程度
- 50,000行以上
- 日本語列名
- 空欄あり
- 数式あり
- CSV UTF-8
- CSV Shift_JIS

## 19. 対象外

初期4本では以下を実装しない。

- ログイン
- 利用履歴のクラウド保存
- メールアドレス収集
- ファイルのサーバー保存
- AI API
- 共同編集
- 有料プラン
- ユーザーファイルを分析目的で保存する仕組み

## 20. 成功条件

- 初見で3〜5秒以内に「何ができるツールか」が分かる
- 非エンジニアが説明書なしでも基本操作を完了できる
- 処理中に固まったように見えない
- エラー発生時に次の操作が分かる
- 結果をファイルとして持ち帰れる
- 4本に統一されたブランドと操作感がある
- 無料ツールとして実用性があり、TI AUTOMATION STUDIOの開発品質を伝えられる
